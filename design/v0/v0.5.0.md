# v0.5.0 — Submit a dataset to NOAA from a local admin page, and keep the correspondence with it

The site's datasets are meant for NOAA's SOS Data Catalog too, which reaches every sphere through its sync.
Submitting one is an email, and so is everything that follows. That correspondence would otherwise live in one
inbox and in a chat history, apart from the datasets it concerns.

## What it decides

**`sos admin` is a page on the maintainer's own machine, not on the site.**
- **Where it runs:** on 127.0.0.1, and it reaches AWS through the aws CLI with the maintainer's own login. No
  public button, login or API exists for anyone else to press.
- **The server's guards:**
  - every request needs a local Host, so DNS rebinding can't reach it;
  - every API call needs the page's per-run token;
  - a browser's Origin, when sent, must be local.
- **Where mail can go:** only to `sos.support@noaa.gov`, NOAA's address for catalog submissions.
- **Turned down:** a "Submit to NOAA" button on the public site. It would need a login system, or anyone could make
  the sending address email NOAA.

**A submission starts from a draft built from what is published.**
- **The source:** `noaa.draft` reads the dataset's entry in the live `datasets.json`.
- **The layout follows NOAA's "Submitting to the SOS Data Catalog" page:**
  - the description, without the credits the playlist appends;
  - notable features the manifest can state: size, length, frame rate, formats, the other lengths, and the
    SOS-labels versions;
  - Dataset Source, Developer, Visualization Developer and Contact, then the full credits;
  - every zip's link, and a simulator link to preview it in a browser.
- **The opening asks NOAA for a review first,** as its "Creating a Dataset" page invites.
- **One line is left for the maintainer:** `[[What presenters should point out…]]`. Sending refuses while any
  `[[...]]` remains.
- **Who it names:** no museum or site. The sender's name and address come from `.env.local`, not from the repo.

**Each email is sent through SES with a copy to the sending address, and that copy is the record.**
- **How it's marked:** the message carries `X-SOS-Forge-Dataset: <slug>`.
- **How it's kept:** the copy lands in the S3 prefix where the sending address's receipt rule stores its mail, and
  NOAA's replies land beside it.
- **How the page files mail:**
  - a sent copy by its mark;
  - a reply by the message it answers (In-Reply-To, then References);
  - anything else by a dataset's name in the subject;
  - what names no dataset is listed apart.
- **A reply's threading:** answering a filed message sets In-Reply-To and References. References is built from
  the parent's References, or from its In-Reply-To when it has none.
- **Status, in words:** not submitted, sent, NOAA replied, or in NOAA's SOS Data Catalog.
- **Sending stays off until replies would be kept:**
  - the page reads the active receipt rule set and allows a send only when an enabled rule takes the address and
    stores it in the configured bucket, under exactly the configured prefix;
  - a broader prefix doesn't count, since it stores mail where the page never lists;
  - until such a rule exists, the page says why.
- **Where the record lives:** the S3 bucket is private and versioned. The local cache is under the sosforge cache
  folder, outside the repo. No correspondence enters the public repo.

**The one public fact is acceptance.**
- **`noaa_catalog`:** a key in `site.toml` holding the dataset's page in NOAA's catalog. The site refuses any link
  outside `https://sos.noaa.gov/`.
- **On the card:** the line "In NOAA's SOS Data Catalog", linked, under the Data line.
- **How it's set:** "Record catalog link" on the admin page writes the key, keeping site.toml's comments, for the
  maintainer to commit.
- **Turned down:** showing "Submitted" publicly. A pending line can sit for months, and a quiet decline would need
  a public edit.

## What it does not decide

- **Receiving mail at the sending address.** stevenpenza.com's receipt rules belong to that site's stack.
  - **What it does:** stevenpenza.com v0.7.12 added a rule for `sos@stevenpenza.com` that stores each message
    under `mail/sos/` in its private bucket, and forwards nothing.
  - **Why no forward:** the correspondence then lives in one place. A reply sent from a mail client would leave a
    thread this page can't see.
  - **Arrival notices:** a setting on stevenpenza.com's admin sends the owner a short notice that mail arrived:
    the sender, subject and time, but no body. Replying to the notice bounces.
- **Delivery, bounce and open tracking.** None of it is recorded. The thread holds what was sent and what came
  back.
- **Which datasets go, and when.** That is the maintainer's call on the page.
  - The aurora dataset was renamed in v0.4.8, so its name now carries its forecast date.
  - Lunar Phases is listed too, though v0.4.6 doesn't send it: NOAA's catalog already has a Moon Phases movie.

## Tested

- **`test_noaa.py`, 4 tests:**
  - the draft against NOAA's checklist, for a movie with lengths and labels and for a still;
  - the `[[...]]` check;
  - message headers and threading, including a parent without References;
  - filing a sent copy, a reply, a reply to a reply, a subject match and unrelated mail, and reading HTML mail;
  - each status;
  - the `site.toml` edit.
- **`test_admin.py`, 4 tests:**
  - **settings:** missing ones named;
  - **readiness from receipt rules:** by address, by domain, an empty recipient list, disabled rules, other buckets,
    and a broader prefix;
  - **the actions end to end over fake ports:**
    - nothing is sent while a placeholder remains, or while mail isn't stored;
    - a send goes only to NOAA, with a copy to the sender;
    - the stored copy and a reply file under their dataset, and the next draft answers with threading;
    - a catalog link is recorded;
  - **the server:** the page's token, a missing or wrong token, a foreign Origin, a foreign Host, a 409 for a send
    that can't be kept, and 404s.
- **`test_site.py` and `test_browser.py`:** `noaa_catalog` validation, and the card showing the link only where it
  is set.
- **The suite:** 161 Python tests and 16 node tests pass, with the browser tests required.
- **By hand against the real account, read-only:**
  - **before the receipt rule:** `state()` listed the published datasets as not submitted and found no rule storing
    `sos@stevenpenza.com`; the page rendered at 1280 px and 390 px with sending off and a banner saying why;
  - **after stevenpenza.com v0.7.12:**
    - the active rule set has an enabled rule taking only sos@ and storing under exactly `mail/sos/`;
    - `state()` is ready, with all five published datasets not submitted and no unfiled mail;
    - the page renders at 1280 px and 390 px with Send enabled, no banner and no page errors;
  - a Getting Richer draft reads as intended. Nothing was sent.
- **Not yet tested:** a real send and a real reply. The first submission is the test: its stored copy should file
  itself under its dataset within a refresh or two.
