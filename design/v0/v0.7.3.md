# v0.7.3 — sos admin sends a test of a NOAA email to Steve's own address first

v0.6.1 and v0.7.2 gave the site's suggestions a test address. The test Steve wanted was of the mail `sos admin` sends
to NOAA: seeing a submission exactly as NOAA would receive it, before the real one goes. Suggestions are back on the
mailbox.

## What it decides

**"Send a test to …" sits beside "Send to NOAA" on every draft.**
- **A button, not a mode:** the real button always goes to NOAA, so there's no switch to forget.
- **The same email:** the same From, subject, text and links, threaded the same way when it answers a message. The
  To header names the test address, and `X-SOS-Forge-Test: 1` marks it.
- **Only to the test address:** there's no copy to the sending address. That copy is how a dataset counts as sent,
  so after a test the dataset is still unsent and the next draft is still the submission.
- **The editor stays open** after a test, so the real send can follow without redrafting. The page says nothing was
  filed and not to reply.
- **The same checks as a real send:** a subject and a message, and no `[[...]]` line left. It doesn't wait for replies
  to be stored, because a test expects none.

**The test address is `SOSFORGE_TEST_TO` in `.env.local`.**
- **Optional:** without it, the button is off and says what to set.
- **Checked at start:** it must be one address, and not the sending address, whose mail is stored with NOAA's.
- **Never in the repo:** `.env.local` is gitignored, and this record doesn't name it.

**A test that does reach the mail store files as unfiled.** It carries its dataset's mark, but `file_mail` puts any
mail marked as a test under "Mail that names no dataset", so it can never make a dataset look sent.

**A malformed test flag is refused.** `/api/send` takes `test` only as true or false. Anything else is a 400, so a
broken request can't fall through to a real send to NOAA.

**The admin server answers `/favicon.ico` with an empty 204,** so the page's console stays clean.

## What it does not decide

- **The suggestion switch from v0.7.2.** It stays, set back to the mailbox.

## Tested

- **`tests/test_admin.py`:**
  - `test_send_a_test`:
    - a test is refused without a test address, and refused with `[[...]]` lines left;
    - it sends while replies aren't stored, only to the test address, with no copy, as the same subject and text
      marked as a test;
    - a stored copy of it leaves the dataset unsent and the next draft the submission.
  - `test_config_names_missing_settings`: the test address is read, and a list, a named address, a non-address or the
    sending address is refused.
  - `test_server_refuses_other_origins_and_tokens`:
    - a test needs the token and a test address;
    - a non-boolean flag is refused, not sent;
    - the favicon gets a 204.
- **`tests/test_noaa.py`:** `message` marks a test only when asked, and `file_mail` files a marked test as unfiled even
  with its dataset's mark.
- **`tests/test_browser.py::test_admin_sends_a_test`:** in Chrome, over the real server with fake ports:
  - the draft offers the test beside the real send, which stays off while replies aren't stored;
  - the test sends the edited text to the test address only, says nothing was filed, and keeps the editor open;
  - without a test address the button is off;
  - the page records no problems.
- **The suite:** 175 Python tests (with the browser tests required), 23 node tests and 23 infra tests pass.
- **Not tested here:** a real test email arriving, which Steve checks with `sos admin`.
