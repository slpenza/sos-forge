# v0.4.8 — Tonight's Aurora becomes Aurora Forecast, named with its date

"Tonight's Aurora" was wrong a day after it was built, and stayed wrong on every sphere that installed it. The
image is one forecast, so its name now says which.

## What it decides

**A dataset's name can take build values, as HUD templates do.**
- **How:** `[dataset] name` may name any value the HUD can use, such as `{forecast_time:%b %Y}`.
- **When it's filled:** at build time, from the first frame's values, after the recipe's own `values` hook, so
  hook values can be used too. The playlist, the README and the gallery card all carry the filled name.
- **Errors:** a value the build doesn't have fails the build, naming the values it does have.
- **Slug:** such a name needs a `slug`, since a slug made from a template would hold its braces.
- **What changes for existing names:** a name with a literal `{` now needs it doubled, `{{`.

**The aurora recipe is `aurora_forecast`, named "Aurora Forecast, 24 Nov 2026".**
- **The name:** `Aurora Forecast, {forecast_time.day} {forecast_time:%b %Y}`, so the day has no leading zero.
  Only the date is in the name; the time stays on the globe's panels.
- **The slug:** `aurora_forecast`, the folder it installs to on a sphere.
- **The card's pill:** "Forecast for 18:52 UTC". The date is already in the title, so the pill gives only the time.
- **This build:**
  - NOAA's forecast for 24 Nov 2026, 18:52 UTC, with a peak of 21%;
  - on data-2026-11 as `aurora_forecast_4k.zip`.
- **Rebuilt rather than renamed in place:** the recipe draws day and night at build time, so the 23 Nov forecast
  can't be redrawn under its own sunlight. The new build is a new forecast.

## What it does not decide

- **The old zip.** `tonight_aurora_4k.zip` stays on data-2026-11. The site no longer lists it; deleting it is a
  separate choice.
- **Old links.** `simulator.html?d=tonight_aurora` now opens no dataset. It was live for two days.
- **Refreshing the forecast.** It is still a snapshot, rebuilt by hand.
