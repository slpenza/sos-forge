# v0.8.1 — A list of private values that no commit may contain, and no plain variables in the workflows

v0.7.4 moved two private values out of the public release logs. This version adopts stevenpenza.com's `secrets`
standard as of its v0.7.19, so the same kind of mistake is stopped before it lands, and the drift check confirms it
for every project. v0.7.4's record calls it v0.7.5; it was renumbered so v0.8.0 could ship while the standard was
settled, and the 360 video recipe that v0.8.0's record calls v0.8.1 moves to v0.8.2.

## What it decides

**`.private-terms` lists what must never appear in this public repo.**
- **The file:** at the project root, one value per line, ignoring case; `#` lines and blank lines are skipped. Git
  ignores it and it is never committed.
- **Where it lives:** a link to an owner-only file in Steve's private folder, so the values never sit in the repo's
  folder. This record doesn't say what they are.
- **Today** no tracked file holds any of them.

**The pre-commit hook refuses a staged line holding a listed value.**
- **How:** `tools/hooks/pre-commit` runs `tools/private_terms.py`, copied from stevenpenza.com, before `scope.py`. It
  reads the staged diff and prints only file:line, never the value.
- **Without a list,** as in a fresh clone, it does nothing.
- **It replaces** the search by hand that ran before each commit.

**The workflows read no plain variables.**
- **Why:** this repo is public, and GitHub prints every step's environment in its logs, masking only secrets.
- **The deploy role's ARN** is now `secrets.AWS_DEPLOY_ROLE_ARN`, because it names the AWS account, which no
  tracked file does. The production variable goes once this version has deployed.
- **`SOS_ZONE_ID`** is dropped. It was never set, and the zone is looked up by name.
- **`PYPI_PUBLISH`** is a secret read through the job's environment, because a step's `if` can't read secrets.
- **`tests/test_workflows.py`** now allows no `vars.` at all outside comments.

**stevenpenza.com's drift check confirms it,** for every project in the standard:
- `.private-terms` is there, ignored and untracked;
- the hook runs the tool;
- in a public repo, no tracked file holds a listed value, reported as path:line only;
- in a public repo, the workflows read no `vars.`.

## What it does not decide

- **Scanning logs.** Neither the drift check nor a release reads run logs: that needs GitHub access to every repo, or
  a release able to delete its own logs. Secrets, masked by GitHub, and the workflow rule do that job instead.
- **Scanning the built site before upload.** The standard leaves it optional, and sos-forge doesn't do it yet.
- **The account ID in earlier release logs.** AWS's role step printed the role's ARN in every release log since
  v0.3.0. AWS doesn't treat an account ID as secret, and Steve chose to keep those logs.

## Tested

- **`tests/test_workflows.py`:** no workflow reads a plain variable, and the release reads the role, the bucket, the
  test address and the upload key as secrets.
- **`tools/test_private_terms.py`,** copied with the tool: the list's comments and blank lines, matching in any
  case, an added line caught at its new number while a removed one and a deleted file aren't, and the hook refusing
  a staged hit without printing the value, and passing a clean commit and a repo with no list.
- **The copies:** `tools/private_terms.py` and `tools/test_private_terms.py` match stevenpenza.com's at d1ffd27 byte
  for byte, and so does the whole of `tools/hooks/pre-commit`.
- **The real list, by hand:** a staged probe file holding one of its values was refused, named as `file:2` with the
  value nowhere in the output, and the tool passed once the file was unstaged and removed.
- **The tracked files:** checked against the list, no hits.
- **The suite:** 185 Python tests (with the browser tests required), 27 node tests and 23 infra tests pass.
