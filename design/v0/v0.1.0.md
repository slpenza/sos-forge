# v0.1.0 — recipes build Science On a Sphere datasets from open data

sos-forge starts as a general tool rather than one dataset. A `recipe.toml` (plus an optional `recipe.py`) says
what to show, and `sos build` fetches, renders, encodes, verifies and packages a folder that deploys to
`/shared/sos/media/site-custom/<slug>/`. The Moon-only pipeline that preceded it becomes the first recipe; its
output is pixel-identical to the original.

## What it decides

**One CLI, five verbs.** `sos new | list | build | still | check`. `--preview` renders 1024×512. Recipes resolve
from `./recipes/<name>` first and then from the bundled `recipes/`.

**Recipes are TOML with typed sections.** The sections are `[dataset]`, `[animation]`, `[hud]`, `[encode]`,
`[playlist]` (verbatim SOS keys), `[assets.*]` (pinned size and SHA-256), and `[[layers]]`. Unknown keys are errors
that suggest the closest valid key. A `recipe.py` may register layers, sources and icons, and may define
`values(t, ctx)` and `checks(ctx, layers)`. The schema is in `docs/recipe-reference.md`.

**Layers are built in.**
- `basemap`: NASA GIBS at the exact output width, a file, or a colour.
- `points`: glow with constant ground size at every latitude; weights, categories, a spotlight cycle, and reveal
  over time with a flash for new points.
- `tracks`: GPX, TCX, FIT and GeoJSON, with the first and last 400 m of each track trimmed and a zoomed inset.
- `lit_globe`: an albedo map lit by a moving Sun, with DEM normals and horizon-map cast shadows, for any body radius.

**Sources are built in.**
- `csv` and `geojson`.
- `tracks`: a fitness app's bulk export of GPX, TCX or FIT files works as-is.
- `overpass`: cached for 30 days, paced, backs off on 429/5xx, and rejects error pages.
- `pinballmap`: the token comes from `$PINBALLMAP_API_TOKEN` and is never cached or logged.

**The projection is fixed.** Pixel centres map to lon = ((x+0.5)/W)·360−180 and lat = 90−((y+0.5)/H)·180, so lon 0
is at X = W/2. Every blur, resample and panel wraps across ±180° without a seam. Compositing is in linear light,
encoded to sRGB once.

**Every build verifies itself.**
- The output is 2:1, and frame 0 shows no seam at ±180°.
- Each layer runs its own checks: the irradiance centroid at X = W/2, the Moon's landmarks, and point and track
  counts.
- The decoded MP4 has the expected codec, size, frame count, frame rate, yuv420p, no B-frames and BT.709 tags.
- A failure stops the build unless `--no-strict` is given.

**Movies follow NOAA's encoding, with H.264 alongside until a site confirms.** Each movie is rendered once and
piped to one ffmpeg per codec.
- **Primary, `dist/<slug>/`:** MPEG-4 Part 2 at 50 Mbps for 4K. Below 25 Mbps is refused, both in the recipe and
  in the encoder. This follows NOAA's content guide, which recommends it and warns that H.264 "can cause errors in
  the SOS software".
- **Variant, `dist/<slug>_h264/`:** H.264 Main, CRF 18, with its own playlist named "<name> (H.264)", so a site
  can compare the two on its sphere.
- Both are yuv420p with no B-frames, a keyframe every second and `+faststart`.
- H.264's BT.709 tags are set in the filter graph, because ffmpeg 9 overrides output-side colour flags.
- `[encode] codecs` or a repeated `--codec` chooses which encodings to build.

**Four recipes ship.** `lunar_phases`, `where_the_world_plays` (OpenStreetMap, ODbL), `pinball_map` (CC BY-SA 4.0,
needs a token) and `my_activities` (your own files; `data/` is gitignored).

**Releases follow stevenpenza.com's scope, secrets and release standards.**
- **Tag-only release.** Only a pushed annotated `vX.Y.Z` tag releases. `release.yml` runs in the `production`
  environment, and so does `tools/release.sh`, which a person can also run by hand. It refuses a dirty tree, an
  untagged HEAD, a tag without its scope doc, or a tag that disagrees with `pyproject.toml`. It then tests, builds
  the sdist and wheel, and creates a GitHub Release whose notes are this file.
- **Release permissions.** `contents: write` is granted only because creating the Release needs it.
- **PyPI.** Trusted publishing from the same job is off until `vars.PYPI_PUBLISH` is `true`.
- **Tests on push.** `test.yml` runs the suite on push and pull requests with Python 3.11 and 3.13, and deploys
  nothing.
- **Pre-commit gate.** `tools/hooks/pre-commit` (blob size limit plus `tools/scope.py`) is enabled per clone with
  `git config core.hooksPath tools/hooks`.
- **Secrets.** `.env.local` is gitignored and loaded by `sos` without overriding the shell. `.env.example` lists
  the names.

## What it does not decide

- **The Pinball Map payload.** The bulk endpoint's field names are normalised defensively, because they could not
  be checked without a token. The first real build may need a tweak.
- **Pitch-level OpenStreetMap detail** (665k soccer pitches) through the public Overpass server. That waits for a
  self-hosted Overpass.
- **Dataset release assets.** MP4 and JPG files are uploaded by hand (`gh release upload`) and never committed.
- **Which codec a given SOS install plays best.** Until NOAA or a site answers, both are built. Once the answer is
  in, the H.264 variant can be dropped or promoted with a one-line change to `[encode] codecs`.
- **Version 1.0.** The recipe schema may still change.

## Tested

- `pytest` on Python 3.13 and 3.11: 107 tests (88 sos-forge and 19 scope-hook) in about 8 s.
  - grid, density, relief and panel maths
  - fetch with stubbed HTTP and backoff
  - recipe validation messages
  - every layer and source; Overpass and Pinball Map are stubbed, and the test confirms the token never reaches
    the cache
  - HUD fitting
  - ffmpeg flags and the 25M floor
  - per-codec video validation
  - the movie build producing an MPEG-4 primary plus an H.264 variant from one render, and the single-codec override
  - playlist and README contents
  - end-to-end texture and movie builds through spawned workers and real ffmpeg
  - cache reuse and invalidation, strict failure, the CLI, and `.env.local` loading
  - the lunar recipe built from the real SVS maps, with its landmark checks failing on rotated, mirrored and
    misregistered maps
- `tools/test_scope.py`, copied from stevenpenza.com unchanged, passes with this repo's `DOCS` and `EXEMPT_DIRS`.
- The lunar port matches the original pipeline at four phases with a maximum pixel difference of 0.
- MPEG-4 Part 2 at 4096×2048 encodes and decodes with the bundled ffmpeg 9.
- `where_the_world_plays` built at 4096×2048 from 110,365 live OpenStreetMap features: 1080 frames, all checks
  passed in both encodings.
- Synthetic builds of the time-reveal and tracks/inset modes were inspected by eye.
- Not tested: the live Pinball Map API, FIT parsing without `fitdecode`, `release.yml` itself (it first runs when
  v0.1.0 is pushed), and playback on SOS hardware.
