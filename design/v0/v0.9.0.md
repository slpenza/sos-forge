# v0.9.0 — sos-forge releases the tool alone; sos.stevenpenza.com deploys from its own private repo

Until now this public repo also deployed sos.stevenpenza.com: its CDK stack, the live settings, and a release that
signed in to AWS and uploaded to private buckets. That's how private values reached public release logs (v0.7.4,
v0.8.2). Steve split it: the tool and its data stay here, and the deployment moves to a private repo, sos-site.

## What it decides

**What stays here, public:**
- the `sos` CLI, the recipes, the tests and the tool's docs;
- the site's pages and scripts, the simulator among them, and `sos site`, which builds them;
- `ask.lock.json` and `package.json`'s `askAnswer` block. corpus.py treats the folder holding them and `docs/` as one
  project, so the pin stays with the docs it builds;
- the dataset releases (`data-YYYY-MM`), which the site's Download links point to;
- PyPI and the MIT licence.

**What moves to slpenza/sos-site, private:**
- `infra/`: the CDK stack, the Suggest, Hit and Status functions and their tests, and the architecture hand file;
- `site/site.toml`, now its `site.toml`: the domain, the gallery list, counting and Help's frame;
- the release that deploys: the site build, `cdk deploy`, the help upload, the architecture chart and the smoke
  check;
- `tools/architecture.mjs` and `tests/test_architecture.py`;
- the deploy secrets: the role, the status bucket, the suggestions test address and Ask & Answer's upload key.

**sos-site builds from a pinned sos-forge tag.** Its `forge.lock.json` names a tag and that tag's commit. Its release
checks out that tag, checks the commit, and runs this repo's `sos site`, `sos upload-help` and `tools/smoke.py`.

**`site/csp.mjs`** is the CSP that CloudFront sends, moved from `infra/lib/`. The browser tests serve the pages under
it here, and sos-site's stack imports this file from its checkout, so one definition holds.

**`sos site`, `sos upload-help` and `sos admin` read `./site.toml`.** Run them from sos-site. `sos admin` records NOAA
catalog links into that file.

**What's new merges both repos.** `sos site --changes <repo>` adds another repo's released For visitors lines. They
are named "site vX.Y.Z" and have no release-notes link, because sos-site's releases are private.

**This repo's release** tests, builds and creates the GitHub Release, plus PyPI when that's on. It signs in to nothing
and reads one secret, `PYPI_PUBLISH`.

**Checks that compared the pages with the server** move beside the server. The Suggest form's checks and licences,
and the download kinds the counter knows, are now tested in sos-site against this repo's `site/js`.

## What it does not decide

- **History.** Everything already pushed stays public in clones and forks. The split keeps only future changes
  private.
- **Counting.** The held change to count visits from browsers that ask not to be tracked, and the move to
  stevenpenza.com's `visits` standard, wait.
- **The production environment's old secrets.** They stay until sos-site's first release has deployed, then go.

## Tested

- **`tests/test_changes.py::test_site_changes_merge_the_deployments`,** with two scratch repos:
  - versions are merged newest date first;
  - the deployment's are named "site vX.Y.Z" and have no link, and sos-forge's keep theirs;
  - with no other repo, What's new holds sos-forge's versions alone.
- **`tests/test_workflows.py`:**
  - no workflow reads a plain variable, and the release reads only `PYPI_PUBLISH`;
  - `test_nothing_here_deploys`: no workflow signs in to AWS, runs `cdk deploy` or reads a deploy secret.
- **`tests/test_browser.py`** serves the pages under `site/csp.mjs`. It fetches the pinned Ask & Answer release from
  `$SOSFORGE_ASK_BASE`, else the live API. That the live `site.toml` hides Help's heading is now tested in sos-site.
- **`site/js/suggest.test.mjs` and `count.test.mjs`** test the pages' own logic. Their comparisons with the server
  are now in sos-site.
- **The suite:** 199 Python tests pass with the browser tests required: the 3 architecture tests went to sos-site and
  1 What's new test was added. 27 node tests pass.
