# v0.5.1 — What's new: the changes a visitor would notice, version by version

The site changed nine times on 23 and 24 November, and a returning visitor had no way to see what was new without
reading release notes written for the maintainer. Those notes cover decisions, tests and internals. A presenter
wants to know which datasets arrived, which changed, and what the site and the tool now do.

## What it decides

**Each scope doc may carry a `## For visitors` section, and the site lists them.**
- **The form:** bullets of `- <Kind>: <what a visitor would notice>`, wrapped lines indented by two spaces.
- **The kinds**, from what Steve asked to cover:
  - new datasets: `New dataset`;
  - revisions to them: `Updated dataset`;
  - what the site and the tool do: `Gallery`, `Simulator`, `Help` and `sos-forge`.
- **Refused at build:** an unknown kind, a bullet without text, or a stray paragraph, naming the doc.
- **Left out on purpose:** a version visitors wouldn't notice has no section, so pins, uploads, tests and the
  local NOAA page never appear.
- **Turned down:** listing every version's title. Half of them are maintenance, and the list would read as noise to
  the people it is for.

**Only released versions appear, dated by their tags.**
- **The list:** `sosforge/changes.py` reads the `v*` tags from git, newest version first by number, and each
  tag's scope doc from the tree being built.
- **Dates and gaps:** a version shows once its tag exists, dated by the tag. A version without a tag (one being
  written) doesn't show.
- **Where it runs:** the release workflow checks out every tag. A copy without tags builds an empty list and logs
  a warning.
- **Each version links to its GitHub Release,** where the full scope doc is the release notes.

**The site shows it in two places.**
- **`changes.html`, What's new:** every version with its date, its number and its lines, each tagged by kind.
- **The home page:** the latest three lines, dated, between the introduction and the gallery, with a link to the
  page. The section stays hidden when there is nothing to show.
- **The nav:** a What's new link on the home page, the simulator and Help, and on the not-found page.
- **The smoke check:** it now loads `changes.html` too.

**The record goes back to v0.3.0,** the first tagged version. Its section, and each later version's that a visitor
would notice, were written for this version: v0.3.0, v0.3.1, v0.4.0, v0.4.2 to v0.4.10. v0.4.1 (browser tests) and
v0.5.0 (the local NOAA page) have none.

## For visitors

- Gallery: a What's new page lists new datasets, updates to them, and changes to the site and sos-forge, newest
  first, and the home page shows the latest three.

## What it does not decide

- **Versions before v0.3.0.** They have no tags, so they don't appear.
- **Linking a line to its dataset.** A line is plain text; the dataset's card is one click away on the home page.
- **A feed (RSS or Atom).** It could be built from the same list if anyone asks.

  - an unknown kind, an empty bullet or a stray paragraph is refused, naming the doc;

    with release links;
  - an untagged doc, a tagged doc without a section and a folder outside git add nothing.

  version's order.
- **`test_browser.py::test_whats_new_lists_visitor_changes`:**
  - the page lists versions newest first, with dates, release links and kind tags;
  - the home page shows the latest three lines, dated, with a link to the page;
  - the nav links What's new;
  - no sideways scroll at 390 px.
  The page also joins the clean-load check under the deployed CSP.
- **The suite:** 165 Python tests and 18 node tests pass, with the browser tests required.
