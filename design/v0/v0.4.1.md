# v0.4.1 — The site tested in headless Chrome, and smoke-checked after every deploy

Until now the gallery and simulator were checked by hand in Chrome, which can't be repeated. That is how the Ask
page shipped with a broken import and sat on "Loading…" for days. This version drives a built site through headless
Google Chrome on every push, under the same Content-Security-Policy CloudFront sends. It also checks the live site
after each deploy.

## What it decides

**Playwright drives the Google Chrome that's installed, not Playwright's own Chromium.**
- The previews are H.264, which Playwright's Chromium can't play.
- Locally that's the Chrome already on the machine; CI installs it with `playwright install --with-deps chrome`.
- Playwright is a dev-only extra: `pip install -e ".[browser]"`. Building datasets never needs it.

**`tests/test_browser.py` builds a fixture site and serves it with the deployed CSP.**
- **The fixture:** two tiny H.264 movies, made by `test_site.py`'s `make_dataset`, and a still.
  - One movie has an extra 3 s length, the SOS-labels style, dates, a pace step (`per = { unit = "day", count = 2
    }`) and a source link.
  - It is built without Ask & Answer, so the Help-to-GitHub fallback is tested too.
- **The CSP has one source:** `csp()` moves from `infra/lib/site-stack.mjs` to a dependency-free
  `infra/lib/csp.mjs`, which the stack re-exports. The tests ask node for it, so a policy change is tested as
  deployed.
- **Without Playwright or Chrome the module is skipped,** so `pytest` still works anywhere. `SOSFORGE_BROWSER_TESTS=1`,
  set in CI, turns a missing browser into a failure, so CI can't skip silently.

**What the tests check:**

| Test | What it checks |
|---|---|
| The problem watcher | It catches a script error, a CSP violation and a 404 on a same-origin file, so "no problems" means something |
| Pages | `/`, `/simulator.html`, `/simulator.html?d=tiny` and `/404.html` load with no console or script errors and no failed same-origin requests. The home page has no `help/` or `ask.html` links, and its two Help links go to the docs on GitHub |
| Cards | Date pill, pace chips ("0.5 s/day", "1.5 s/day"), "1 s in all", "Painted / SOS labels" and the Data line |
| Card choices | Clicking a pace, clicking "SOS labels" and pressing ArrowLeft each set Download's wording and link. A one-length movie keeps "1 s loop", and the still keeps "Still image" with no play button |
| Flat preview | Play swaps in a video that really plays, with 30 caption cues showing at the top. Starting the second preview pauses the first |
| Simulator | The caption follows the frames and keeps its centre and top while the globe is dragged (its width follows the text) |
| Smoke check's list | `download_urls` covers each dataset's own downloads and every length in both styles |

**`tools/smoke.py` checks the live site after every deploy.**
- It loads `/`, `/simulator.html`, `/help/` and `/404.html` in headless Chrome. It fails on any console error, script
  error, CSP violation or failed same-origin request.
- It fetches the first byte of every download on every card.
- It is the last step of `release.yml`, after `release.sh` deploys. A failure marks the release run red, and means
  the deploy needs a look.
- The tests reuse its page watcher.

**CI gains a `browser` job** in `test.yml`, beside the Python matrix and the site job. It adds about a minute, most
of it installing Chrome.

## What it does not decide

- **Safari and Firefox.** Playwright's WebKit and Firefox could run the same tests, but neither plays H.264 in every
  CI image. Chrome first.
- **Visual comparison against screenshots.** The tests check behaviour and wording, not pixels.
- **The help pages' own behaviour.** Those belong to Ask & Answer. The smoke check only requires `/help/` to load
  clean.
- **Hand releases.** `release.sh` doesn't run the smoke check, because Playwright isn't needed to release. Run
  `python tools/smoke.py <site>` after a hand release.

## Tested

- **`pytest`:** 146 tests, 9 of them in headless Google Chrome. They run in 17 s.
- **Two of the first failures were in the tests, not the site:**
  - **The chip click:** Playwright refused to click a chip's text because the invisible radio input covers it.
    The tests now click the label, as a person does.
  - **The caption check:** it compared the caption's exact box, which changes width as "Frame 9" becomes
    "Frame 12". It now compares the centre and top.
- **Infra:** `npm test` passes all 5 tests with `csp()` moved to `csp.mjs`.
- **Node:** 11 tests.
- **The smoke check against the live v0.4.0 site:** 4 pages and 28 downloads, all good.
- **Workflows:** `test.yml` and `release.yml` parse.
- **Not yet tested:** the new CI job and the release smoke step on GitHub's runners, which first run on this
  version's push and tag.
