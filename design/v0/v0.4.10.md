# v0.4.10 — Each release uploads the help docs it committed, and Help drops its frame

Ask & Answer used to read sos-forge's docs from a checkout on its own deployment, whatever was committed there.
It no longer does. Under the `ask` standard's "own upload" rule, Steve approved sos-forge uploading its own docs
with its own key, so a docs change reaches Help only when sos-forge sends it. Separately, Ask & Answer v0.19.15
drops the desk layout's frame around the Help panel.

## What it decides

**A release uploads the help docs after the site deploys.**
- **The command:** `sos upload-help` runs the `corpus.py` that `ask.lock.json` pins, fetched and checked against
  the lock as the site build's is. It runs it with `--project . --upload <ask_base> --key-env ASK_UPLOAD_KEY`.
- **Where it runs:** `tools/release.sh` runs it after the CDK deploy, so the docs a tag commits reach Help with
  the site that tag builds.
- **The key:**
  - `ASK_UPLOAD_KEY`, a repository secret that `release.yml` passes to the release step;
  - it reaches `corpus.py` through the environment, never the command line, so it never lands in a log;
  - it is scoped by Ask & Answer to the `sos` project, at most 14 documents and 16,000 tokens.
- **No key, no release:** `release.sh` refuses up front when it is missing, before anything is published. A site
  shouldn't go live while Help answers from older docs.
- **Turned down:** uploading on every push to main. Help would then describe code the site doesn't run yet.

**Help pins Ask & Answer v0.19.15.**
- **What changes:** on the desk layout, the panel has no background, border or padding of its own.
- **Why:** with the panel at the page's width since v0.19.14, the frame was a box inside the page that cost
  phones about 40 px of text width.
- **Where it was asked for:** Steve chose to drop it for every desk site, which also covers Pinball's placards
  help.
- **What else it changes:** only `docsite/index.html`; the other six pinned files are unchanged.

## For visitors

- Help: answers come from the docs as of each release, and the answer panel no longer sits in a box, which gives
  phones more room.

## What it does not decide

- **Who holds the key.** Steve moves it from `~/.config/ask-answer/sos-upload-key` into the repository's secrets,
  then deletes the file.
- **The docs' content.** The first upload carries what v0.4.6 to v0.4.9 changed in `docs/`, which isn't on Help yet.

## Tested

- **`test_site.py::test_upload_help_uses_the_pinned_corpus`,** against a stand-in API:
  - without `$ASK_UPLOAD_KEY` it refuses and runs nothing;
  - with it, the pinned `corpus.py` runs with `--upload` to the base (trailing slash removed) and `--key-env
    ASK_UPLOAD_KEY`, and sees the key only in its environment;
  - a `corpus.py` changed on the server is refused before anything is uploaded.
- **`release.sh`:** it parses (`bash -n`).
- **The corpus, built locally without uploading:** v0.19.15's `corpus.py --project . --json` builds 7 documents,
  8,028 tokens, inside the key's limits.
- **The pin:** v0.19.15's `corpus.py` matched the sha384 `GET /ask` lists. `--lock` moved the pin from v0.19.14 to
  v0.19.15, changing only `docsite/index.html`.
- **Help, built locally from v0.19.15,** with the API stubbed (its real manifest and a canned four-page answer):
  - the panel has a clear background, no border and no padding;
  - at 390 px the prose takes 354 px, up from 312;
  - at 1440 px the four references sit beside it;
  - no page errors and no sideways scroll.
- **The suite:** 153 Python tests and 16 node tests pass, with the browser tests required. This includes the
  home ask box and the help layout, built from the pinned v0.19.15 under the deployed CSPs.
- **v0.4.9, live, before this version:**
  - one real question on sos.stevenpenza.com's Help, "can i add my own dataset?", came back "Combined from 4
    pages";
  - it cited deploying, getting started, the recipe reference and the simulator, each with a verbatim quote and
    an Open · line link;
  - no page errors, still inside the frame this version removes.
- **Not tested here:** a real upload. The first release with the key in its secrets is the test, and Ask & Answer's
  `GET /status` shows when it lands.
