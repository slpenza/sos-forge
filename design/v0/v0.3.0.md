# v0.3.0 — Gridded data, countries shaded by year, and points that grow

Until now sos-forge drew points, tracks and a lit globe. This version adds the three other kinds of data that most
public datasets come in:
- a value on a regular latitude/longitude grid
- a value per country per year
- places whose size changes year by year

It also adds a day and night layer lit by the Sun's real position. Three demo recipes show them off: Tonight's
Aurora, Getting Richer and Cities Growing.

## What it decides

**Three new layers, all reading registered sources, so a recipe stays TOML.**
- **`grid`:**
  - Samples a gridded source onto the output bilinearly, wrapping when the grid spans 360°, so there is no seam
    at ±180°.
  - Colours it once in `prepare`.
  - `blend = "add"` adds it as light; the colour ramp carries the strength, and `opacity` scales it.
  - `blend = "over"` paints over the layers below, covering more where values are higher.
- **`regions`:**
  - Rasterises the polygons once into a 16-bit ID image with `cv2.fillPoly`, largest first, so enclaves (Lesotho
    in South Africa) land on top. It draws anti-aliased borders as a second mask.
  - Each frame looks every region's value up for the frame's fractional year, colours a per-region table, and
    indexes it with the ID image. That costs the same however many regions there are.
  - Values are interpolated between data years, geometrically on a log scale so steady growth looks steady. They
    are held at most one year past a region's first and last value, so nothing is invented for years a source
    never estimated; those regions show as "no data" grey.
  - Regions that share a code share its value. Natural Earth gives Australia's offshore territories the code
    AUS, and without this Australia read as "no data".
  - A colour-bar legend is drawn as a gnomonic panel at 46°S, under the HUD's anchors, with round 1-2-5 ticks on
    log scales.
- **`daylight`:**
  - Shows a day image where the Sun is up and a night image where it is down, blended with a smoothstep over a
    12° twilight band.
  - The Sun's position comes from `sosforge/sun.py`: the Astronomical Almanac's low-precision formula, good to
    about 0.01° for 1950–2050. No ephemeris dependency.
  - `at` is `timeline` (each frame's date), `now`, or an ISO date-time. `now` is frozen in `prepare`, so every
    worker and frame draws the same moment.

**Six new sources, still with no new dependencies.**

| Source | What it reads | How it is fetched |
|---|---|---|
| `swpc_aurora` | NOAA SWPC's OVATION JSON, 360×181 cells, kept with its observation and forecast times | Cached for 30 minutes |
| `natural_earth` | Natural Earth v5.1.2 countries, keyed by `ISO_A3_EH`, falling back to `ADM0_A3` where that is −99 | A pinned asset with size and SHA-256 checks |
| `geojson_regions` | Your own polygons | A local file |
| `owid` | Any Our World in Data chart by its slug: the full CSV, with the citation and unit from its metadata | Cached for 30 days |
| `table` | Your own CSV of code, year and value | A local file |
| `ghsl_ucdb` | The GHSL Urban Centre Database R2024A, read from its GeoPackage | A pinned 37 MB asset, read with the standard library |

For `ghsl_ucdb`, `sqlite3` reads the table; the geometry blob's header is skipped (honouring any envelope) and the
WKB point decoded. The points are in World Mollweide (ESRI:54009), so they are inverted to latitude and longitude
in closed form. GDAL would have been a heavy install for one table.

**Points that grow.**
- **`weight_series = "MT_POP_TOT_{year}"`:** finds every matching column, interpolates each point's weight by the
  frame's year, and keeps a point dark until it has weight. It replaces `weight` and `time`.
- **`weight_ref`:** a number, or `"auto"` for the 99th percentile. It sets the weight drawn at full strength, so
  large weights such as populations don't saturate every glow.
- **Totals stay raw:** `weight_sum` is the real total, so templates can say how many people.
- **Weights are scaled at draw time:** the layer now keeps raw weights and applies `weight_scale` and `weight_ref`
  when drawing. Existing recipes render the same.

**Smaller changes the layers needed.**
- **Timeline:**
  - Every dated frame now has a `year` template value.
  - Fractional years count the time of day and leap years.
  - `parse_date` converts ISO offsets to UTC instead of discarding them.
- **Values hook:** a `values(t, ctx, vals)` hook with three parameters receives the layer values gathered so far.
  Two-parameter hooks work as before. `cities_growing` uses it to put "3.6 billion" in words.
- **Colour ramps:** they move from the tracks layer to `sosforge/colormaps.py`, which adds `aurora`, `wealth` and
  `sea`.

**Demo recipes.** All three put their HUD and legend over open ocean at 30°S (anchors −20, 90 and −140), clear of
Africa and New Zealand.

| Recipe | Output | Data | Notes |
|---|---|---|---|
| `tonight_aurora` | still image | NOAA SWPC OVATION | The forecast over the real day and night at build time; the HUD gives the forecast time |
| `getting_richer` | 40 s movie, 1820–2022 | Maddison Project Database 2023 via Our World in Data, on Natural Earth borders | Log scale from $500 to $60,000. The description says the borders are today's |
| `cities_growing` | 22 s movie, 1975–2030 | GHSL R2024A urban centres | Weight `sqrt` with `weight_ref = "auto"`. Of the three scales compared on 1975 and 2025 frames, it was the one where West Africa and South Asia brighten visibly without small towns vanishing. A hook adds "(projected)" after 2025 |

**The gallery takes datasets from a data release, not the version release.** The v0.2.0 flow had a gap:
1. `release.sh` creates the version's release when the tag is pushed.
2. It then builds the site, which downloads dataset zips that can only be attached by hand afterwards.
3. So the first deploy of any new dataset would fail.

The fix:
- `site.toml` points every dataset at a release tagged `data-2026-11`. Steve creates it by hand with the zips
  from `sos bundle`. Its tag doesn't match `v*`, so it deploys nothing.
- The `v0.3.0` tag then deploys a site that can already download everything.
- Where the World Plays moves to this release too: the repo was recreated, so the `v0.1.0` release it named no
  longer exists.

**Release zips download through GitHub's asset API when a token is present.** The recreated repo is private, and a
private release's public download link answers 404.
- `release_asset` asks the asset API, with the token, for the signed address without following the redirect.
- It then downloads from that address without the token, so the token never reaches the storage host.
- Without a token it still uses the public link.
- CI already passes `GH_TOKEN` to `release.sh`.

**The help page's frame moves out of `package.json`, as Pinball's did.** The deployed Ask & Answer (v0.18.1) builds
its corpus from `package.json` and refuses `title`, `bar` and `groups`, which arrived in v0.19.1. Adding sos-forge
to the deployment would have broken every check it runs, and our own strict site build would have failed too.
- **`package.json`:** its `askAnswer` block keeps only `key`, `label`, `docs`, `url` and `head`.
- **`site.toml`:** a new `[help]` section holds the frame (`bar`, `title` and `groups`, whose topics must exist)
  and `release = "v0.19.1"`.
- **The build:** `build_help` adds the frame to a temporary copy of the project (`package.json`, the docs and the
  fragments) and runs that release's `corpus.py` on it.
- **Where each piece comes from:** `sos site` reads `client/` at `ask_release` and `tools/` at the `[help]` release
  out of the ask-answer clone's history with `git archive`. Whatever the clone has checked out no longer matters.
- **`--strict-ask`:** now means both tags must exist. Without it, a missing tag falls back to the clone as it
  stands, with a warning.
- **Repinned to v0.19.1:** the deployment moved to v0.19.1 before this tag, so `ask_release` follows it and the
  `[help]` release is dropped. The help pages now default to `ask_release`. `client/` is unchanged between the two
  tags, so the panel files are the same bytes. The frame stays in `site.toml` even though v0.19.1's `corpus.py`
  would accept it in `package.json`: there the frame never depends on which release the deployment runs.
- **Each pinned path gets its own folder:** with both pins on one tag, extracting `tools/` wiped the `client/` just
  extracted into the same `ask/<tag>` folder, and the build failed. Each path now goes under `ask/client/<tag>` or
  `ask/tools/<tag>`.

**v0.2.0's OIDC subject is corrected.** The recreated repo's ID is 1468118461, so the trusted subject is
`repo:slpenza@11827313/sos-forge@1468118461`. `design/v0/v0.2.0.md` is updated to match, because its external
steps have not been applied yet.

## For visitors

- New dataset: Getting Richer: average income per person in every country from 1820 to 2022, on a colour scale
  with a legend.
- New dataset: Cities Growing: about 11,700 urban centres glowing by population from 1975 to 2030, with projections
  marked.
- New dataset: Tonight's Aurora: NOAA's aurora forecast, drawn over the real day and night when it was made.

## What it does not decide

- **Hiding the aurora on the day side.** OVATION forecasts the whole oval and NOAA's own viewer shows it all, so the
  layer does too. A `night_only` mask is a small follow-up if presenters want it.
- **Refreshing Tonight's Aurora automatically.** It is a snapshot. A scheduled rebuild belongs with live data,
  which is still out of scope.
- **Historical borders.** Getting Richer shades today's countries in every year, and says so.
- **Countries and territories that Maddison doesn't cover.** They stay grey. 167 of Natural Earth's 242 regions
  have data in some year.
- **Gridded sources beyond OVATION** (for example sea-surface temperature or NetCDF). `GridField` is the
  interface they will fill.
