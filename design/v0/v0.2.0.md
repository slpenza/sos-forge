# v0.2.0 — sos.stevenpenza.com: gallery, simulator, help and Ask, deployed only from a tag

Until now a dataset could only be judged on a sphere. This version gives sos-forge a home: a gallery of published
datasets, a browser simulator of a 6-foot sphere, the help as Ask & Answer pages, and an Ask panel scoped to
sos-forge. It also makes text that stays still on the sphere a first-class output.

## What it decides

**The site is built from three inputs.**
- **`site/`:** hand-written pages for the gallery, simulator and Ask, the stylesheet and the scripts.
- **The published datasets:** listed in `site/site.toml`.
- **Ask & Answer:** a pinned checkout supplies the help pages and the panel.

`sos site` puts them together in `build/site/`. With `--serve` it previews the result locally.

**Datasets reach the site as release zips, never as CI renders.** A dataset takes minutes and live data to
build, so:
1. It is built on a workstation.
2. `sos bundle <slug>` zips the dataset's folders, one per encoding.
3. The zips are attached to a GitHub Release by hand.
4. `site.toml` names the release and the zip for each dataset.

The site build then downloads the H.264 zip. It makes a 2048-wide H.264 preview and a poster, writes
`datasets.json`, and links both zips for download. A local build reads `dist/` folders instead.

**The simulator.**
- **Rendering:** WebGL2 with no 3D library. One full-screen shader casts a ray per pixel, intersects the sphere
  exactly and samples the frame by latitude and longitude, so there are no facets, no pinched poles and no seam
  at ±180°.
- **Playback follows `playlist.sos`:**
  - the frame rate, as a playback rate
  - `firstdwell` and `lastdwell`
  - `animate`
  - spin (`zfps` × `zrotationangle`), with a fixed rate for textures
  - the `tiltx`, `tilty` and `tiltz` tilts
- **Views:**
  - **Orbit:** a view of the whole sphere.
  - **Visitor:** eye level for an adult 1.2 m from a 6-foot sphere, with 30°S at eye height and a 70° field of
    view.
- **Your own dataset:** you can drop a dataset folder onto the page; nothing is uploaded. Browsers can't play
  MPEG-4 Part 2, and the page says so and points to the `_h264` folder.
- **Tested logic:** the geometry and playlist logic are pure modules tested under `node --test`.

**Text that stays still.**
- **Labels on every movie:** every movie build writes `labels.txt`, one line per frame: the HUD title, then the
  subtitle after a middle dot. It adds `label = labels.txt` to the playlist, an SOS feature that draws the text
  four times around the sphere at a fixed position.
- **`[hud] mode`:**
  - `"panels"` (the default) keeps the styled panels in the frames and ships the labels hidden
    (`labelvisible = false`), for presenters to switch on.
  - `"labels"` prints no panels into the frames and shows the labels.
- **In the simulator:** the **Caption** button shows the same lines fixed at the top of the view.

**Help and Ask.**
- **Settings:** `package.json` holds the askAnswer block: key `sos`, address `https://sos.stevenpenza.com/help`,
  the site's `head` and `bar`, and four groups of pages.
- **Help pages:** built with the pinned checkout's `corpus.py --docs-out`.
- **Panel files:** copied from its `client/`. `site.toml` pins `ask_release = "v0.18.1"`, the release the
  deployment runs; the deployed API publishes no client files until v0.19.0.
- **API address:** never in the repo. `config.json` gets it from `$SOSFORGE_ASK_BASE`.
- **Scope:** the Ask page mounts the panel limited to `sos`.
- **New help:** `docs/simulator.md` covers the simulator and text that stays still.

**`infra/` is a JavaScript CDK app (`SosForgeSite`) on bootstrap qualifier `sos1`**, set in `cdk.json` as
stevenpenza.com's v0.3.0 standard asks. It contains:
- a private storage bucket that only CloudFront can read (origin access control)
- a CloudFront distribution requiring TLS 1.2 (2021 policy) or newer, with a DNS-validated certificate for
  `sos.stevenpenza.com`
- A and AAAA records in the `stevenpenza.com` zone
- a viewer function that maps folder URLs to `index.html` and redirects `/help` to `/help/`
- two response-header policies: a strict CSP (no inline script) for the site, and inline script only under
  `/help*`, which the help viewer needs; Ask's origin is the one other origin either allows
- a deployment step that uploads the built site and invalidates the cache
- a `project=sosforge` tag

The public repo names no account, zone ID or API address. Those come from the environment.

**A tag deploys the site; nothing else does.**
- **`tools/release.sh`:** after the GitHub Release, it builds the site with `--strict-ask`, so the ask-answer
  checkout must be at the pinned tag. It then runs `cdk deploy` as `sosforge-deploy-role`: through OIDC in CI,
  or the `sosforge-deploy-role` profile by hand. Release creation is skipped when the release already exists, so
  a failed site deploy can be rerun.
- **`release.yml`:** checks out `slpenza/ask-answer` at the pinned tag with a read-only deploy key, then reads
  the role, the API base and the optional zone ID from the `production` environment.
- **`test.yml`:** gains a `site` job (simulator logic plus synth tests) that deploys nothing.

**Changes outside this repo, each made by its owner and approved by Steve:**
- **stevenpenza.com's `account-stack.ts`:**
  - A `PROJECTS` entry `{ name: 'sosforge', qualifier: 'sos1', moved: true, release: { subjects:
    ['repo:slpenza@11827313/sos-forge@1468027271', 'repo:slpenza/sos-forge'], reads: [] } }`.
  - `trustRelease` skips the S3 read grant when `reads` is empty.
  - Then `npm run deploy:account`.
- **The `sos1` bootstrap:**
  ```
  cdk bootstrap --qualifier sos1 --toolkit-stack-name CDKToolkit-sos1 \
    --cloudformation-execution-policies arn:aws:iam::aws:policy/AdministratorAccess aws://<account>/us-east-1
  ```
- **Local profile:** a `sosforge-deploy-role` profile in `~/.aws/config`, assuming the role from `steve-cli`.
- **GitHub `production` environment:** variables `AWS_DEPLOY_ROLE_ARN` and `ASK_API_BASE` (and optionally
  `SOS_ZONE_ID`), and the secret `ASK_ANSWER_KEY`, a read-only deploy key added to `slpenza/ask-answer`.
- **`ask-answer-deploy/deploy.json`:**
  - `"../sos-forge"` in `corpus`
  - a `notify` entry for `sos`
  - `"https://sos.stevenpenza.com"` in `allowed_origins`
- **stevenpenza.com's `projects.toml`:** a row, without `index = true`.

## What it does not decide

- **Visits and an owner `/analytics` page** (stevenpenza.com v0.6.0): they wait for the project's own passkey
  sign-in, as that standard allows.
- **Gridded data and country shading:** v0.3.0, which adds aurora, getting richer and cities growing to the
  gallery.
- **Live data and pushing datasets to a running SOS.**
- **Fetching the panel from Ask & Answer's published files** instead of a checkout. That waits for its v0.19.0
  deployment.
- **Whether SOS labels stay fixed when a presenter rotates the globe.** NOAA documents their placement relative to
  each projector but not their behaviour under rotation. Confirm on a sphere.
- **`labelformat` styling of labels:** NOAA says to make that file with its Visual Playlist Editor.

## Tested

- `pytest`: 116 tests, including:
  - the site builder on a real tiny H.264 dataset: bundles, safe unzip, previews, labels, release downloads with
    stubbed HTTP and the token only on the API call, and assembly with a stand-in ask-answer checkout
  - `[hud] mode`
  - label lines in both encodings
  - playlist label keys
  - the CLI's `bundle` and checkout resolution
- `node --test site/js/*.test.mjs`: 6 tests of playlist parsing and defaults, the data-file lookup, orientation
  (lon 0 in front, east to the right, eastward spin, tilt), the orbit camera, and the Visitor view's eye level.
- `cd infra && npm test`: 5 synth tests:
  - the private bucket with origin access control
  - the aliases, certificate and A/AAAA records
  - the strict CSP with inline script only under `/help*`
  - the upload with invalidation
  - the viewer function's index and redirect rules
- `cdk synth` of the real app uses `cdk-sos1-*` roles throughout.
- **In Chrome** against `sos site --serve` built from the 4K Where the World Plays:
  - the simulator plays, Orbit and Visitor frame the sphere, and portrait windows fit
  - the caption stays put while the sphere is dragged
  - the gallery cards and the help index render in the site's frame, and the console is clean
- Ask & Answer's `corpus.py` reports 7 documents under key `sos` with the public address declared.
- Where the World Plays rebuilt at 4096×2048: 17 checks pass, and `labels.txt` has 1,080 lines.
- **Not tested:**
  - an AWS deploy, which needs the bootstrap and the role
  - the Ask panel answering, which needs the `deploy.json` changes
  - the viewer function inside CloudFront itself
  - SOS labels on hardware
