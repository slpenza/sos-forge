# v0.4.0 — Download a movie at the pace your show needs, with its text painted or as SOS labels

Until now every movie had one length, fixed in its recipe, and one way of showing its text: painted into the
picture, where it turns with the globe. A presenter with a two-minute slot had to rebuild the movie, and a site
whose SOS shows labels had no clean version. This version builds movies at other paces and with SOS labels, lets
the gallery offer both, and makes the cards easier to read: captions on the flat preview and a link to each
dataset's source.

## What it decides

**`sos build <slug> --seconds N` re-renders a movie at another length.**
- The frame count becomes N × the recipe's fps, and every frame is rendered afresh.
  - Values between data years are interpolated per frame, and a sports cycle divides its time evenly.
  - So a slower version is as smooth as the standard one, not stretched or stuttering.
- The playlist's `fps` doesn't change. Slowing a movie by lowering it would stutter, and NOAA doesn't say whether
  SOS honours `fps` for a movie file.
- Whole seconds only, 1 or more. `--seconds` with `--frames`, or on a still image, is refused.

**`sos build <slug> --hud labels` builds the movie with SOS labels instead of painted text.**
- No text panels are painted into the frames. `labels.txt` is switched on in the playlist (`labelvisible =
  true`), so SOS draws the text, which can stay put while the globe turns.
- A colour legend, such as Getting Richer's, is an image, not text, so it stays painted. Moving it to SOS's
  picture-in-picture overlay (`pip`) waits until labels and overlays are confirmed on a real sphere.
- `--hud panels` does the reverse for a recipe whose own mode is labels.
- **The worker fix:** worker processes reload the recipe from disk, which lost the switch, so the first smoke
  test still had panels painted in. `BuildContext.to_args()` now carries the HUD mode to the workers.

**A version other than the recipe's own is tagged everywhere, so versions install side by side.**
- **Folders:** `dist/<slug>_<N>s/`, `dist/<slug>_labels/`, `dist/<slug>_<N>s_labels/`, plus `_h264` copies when
  H.264 is built.
- **Data files:** `<stem>_<N>s_labels_4k.mp4`.
- **Playlist names:** "Getting Richer (2 min)", "Getting Richer (2 min, SOS labels)". They show up as separate
  entries in the SOS library.
- **README:** it names the version, such as "This is the **2 min** version (3,600 frames at 30 fps)", and for
  labels says SOS draws the text.
- The recipe's own length and style stay untagged, so existing folders, zips and links keep their names.
- `sos bundle <slug>` zips every version it finds under the same tags.

**Extra lengths and the labels style ship as MPEG-4 only.**
- Cards link MPEG-4, which NOAA recommends.
- H.264 stays for the standard length only, where the site needs it for previews and presenters can compare
  codecs.
- This halves the upload.

**`site.toml` describes each dataset's versions, pace and sources.**
- **`lengths = [20, 101, 202]`:** the extra lengths in seconds. Each is expected on the release as
  `<slug>_<N>s_<rest of the first download>`.
- **`label_style = true`:** every length is also on the release as `<slug>[_<N>s]_labels_…`.
- **`per = { unit = "sport", count = 9 }`:** the step a movie's pace is measured in. Dated movies take years from
  their recipe's span, so only Where the World Plays sets it (8 sports and the all-sports map).
- **`sources = [{ label, url }]`:** the links behind each card's "Data:" line.
- Each `datasets.json` entry gains:
  - `lengths`: shortest first, each with its seconds, its downloads, its `labels` download or null, and
    `default` marking the length the preview plays.
  - `per`
  - `sources`

**The card offers pace and text style, and Download follows both.**
- **Pace chips:** a movie with several lengths shows them by pace ("0.1 s/yr | 0.2 s/yr | 0.5 s/yr | 1 s/yr"),
  because presenters compare datasets by how fast time moves. The total sits beside them ("1 min 41 s in all"),
  and the button says it too ("Download 1 min 41 s").
- **Style chips:** "Painted | SOS labels" sit beside Download when the dataset offers labels.
- Both are native radio buttons styled as joined chips, so arrow keys and screen readers work.
- A movie with one length keeps its pill and shows its pace beside it.
- `site/js/lengths.js` holds the length and pace wording as pure functions with node tests. The length wording
  matches the playlist's `length_label`.

**The flat preview shows the labels as captions.**
- Text drawn for a sphere is small and stretched on a flat map. Pressing play now loads `labels.txt` and adds a
  native caption track pinned to the top: "1923 · Average income per person".
- Native captions also show in full screen, and the player's CC button turns them off.
- `site/js/captions.js` groups each run of identical lines into one cue, timed by the source frame rate.

**Each card links its data source.** A "Data:" line under the description links the primary sources:

| Dataset | Data line |
|---|---|
| Getting Richer | Maddison Project Database 2023 · Our World in Data |
| Cities Growing | GHSL Urban Centre Database R2024A, through its DOI |
| Where the World Plays | OpenStreetMap contributors, linking the copyright page |
| Tonight's Aurora | NOAA SWPC's OVATION forecast |

Now that the preview plays on the card, this puts the CC BY credit beside it. The full credits still travel in
every README and playlist.

**Where the World Plays gets a date pill: "Mapped as of 22 Nov 2026".**
- It steps through sports, not time, so it has no span. But OpenStreetMap keeps changing, so the date its data was
  fetched is worth showing.
- The standard zip and every pace were rendered from the same cached Overpass results, fetched that day.
- It is a `site.toml` `dates` value, like Tonight's Aurora's forecast time.
- "As of" rather than "by", which can read as a name.

**The site refuses to deploy a download its release doesn't hold.**
- `sos site` lists each release once and checks every download, length and style against it. A missing one fails
  the build with its name, so a card can't link a zip that was never uploaded.
- A release that can't be listed (offline) is warned about and skipped.
- `--no-check-downloads` skips the check. Tests call `build_site` without it.

**`ask_release` follows the deployment to v0.19.3.**
- `site.toml` says to keep it equal to the deployed Ask & Answer, which moved to v0.19.3. That release published
  sos-forge's docs at `feccfe1`.
- `client/` is byte-identical to v0.19.1's, so the Ask panel files don't change.
- v0.19.3's `corpus.py` builds the same 8 help pages with the `[help]` frame.
- The home-page ask box still waits for the layouts release that comes after v0.19.3.

**The regions layer's cache version goes to 2.**
- Layer caches are keyed by type, version, options, inputs and resolution, not by code.
- When v0.3.0 made every region sharing a code get its values, the cached matrices made before kept Australia's
  mainland empty.
- The 1024-wide preview cache was one of them, and a smoke test showed Australia grey. Bumping `VERSION`
  rebuilds them.

## What it does not decide

- **Further paces.** This version offers these, in both text styles, on `data-2026-11`:

  | Movie | Paces | Totals |
  |---|---|---|
  | Getting Richer | 0.1, 0.2 (standard), 0.5 and 1 s/yr | 20 s, 40 s, 1 min 41 s, 3 min 22 s |
  | Cities Growing | 0.2, 0.4 (standard), 1 and 2 s/yr | 11 s, 22 s, 55 s, 1 min 50 s |
  | Where the World Plays | 2, 4 (standard), 8 and 15 s/sport | 18 s, 36 s, 1 min 12 s, 2 min 15 s |

  Another pace is one `sos build --seconds` away for anyone with the tool.
- **Rendering in the visitor's browser.** Browsers can't encode MPEG-4 Part 2 natively. Shipping ffmpeg as
  WebAssembly would be slow at 4K and would make the site a distributor of FFmpeg. A pace that isn't offered is
  one `sos build --seconds` away for anyone with the tool.
- **A pace picker in the simulator.** The simulator and the card's flat preview play the standard length.
- **Dates written into the bundle.** Still taken from the recipe, as in v0.3.1.

## Steve's steps for this release, in order

1. Render every pace in both styles at 4K:
   - painted: `sos build <slug> --seconds N`
   - labels: `sos build <slug> --hud labels --codec mpeg4 [--seconds N]`
2. Bundle them with `sos bundle <slug>`, which re-zips the standard ones unchanged.
3. Upload only the new MPEG-4 zips: `gh release upload data-2026-11 <zips>`.
4. Add `lengths` and `label_style = true` to each movie in `site/site.toml`.
5. Commit, then tag and push `v0.4.0`. The site build checks every zip is there before it deploys.

## Tested

- **`pytest`:** 137 tests. New and changed ones cover:
  - a `--seconds 1` build of the tiny movie:
    - 30 frames that pass every check
    - tagged folders, data files and playlist names for both codecs
    - the README's version line, and 30 labels
  - a `--seconds 1 --hud labels` build in two worker processes:
    - in the pixels where the two styles differ, its first frame matches an in-process labels rendering, and the
      painted build's matches a panels rendering
    - with the worker fix removed, this fails ("workers drew panels")
    - its playlist reads "Tiny Movie (1 s, SOS labels)" with `labelvisible = true`
  - `sos bundle` naming all three zips with their tags
  - an untagged build when the length or style matches the recipe's
  - refusing:
    - `--seconds` with `--frames`
    - `--seconds 0`
    - `--seconds` or `--hud` on a still
    - an unknown `--hud`
  - `length_label` for seconds, whole minutes, and minutes with seconds
