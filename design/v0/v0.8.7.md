# v0.8.7 — The shared legend scale keeps its values' precision, so v0.8.6's dataset can ship

v0.8.6's release stopped at its tests on CI's Python 3.13, before building or deploying anything. Its zip was already
on the `data-2026-11` release, with nothing yet linking to it. A pushed tag never moves, so this version carries
v0.8.6's dataset, Where 8 Billion People Live, with the fix. What's new lists the dataset under v0.8.6, where it was
decided.

## What it decides

**`legend.scale01` works in its values' own precision.**
- **What broke:** v0.8.6 moved the legend's scaling out of the regions layer and cast every value to float32 on the
  way. In float32, log10(100) isn't exactly 2 on CI's Linux build of Python 3.13, so Getting Richer's lowest legend
  value mapped to 0.0000001 instead of 0. Its test caught it there; the Mac running the suite before the tag gave
  exactly 0.
- **The fix:** no cast. A float64 value is scaled in float64, as the regions layer always did, and the grid layer's
  float32 field stays float32, so its memory doesn't double.

## What it does not decide

- **Running the suite on Linux before a tag.** CI does, after the push. A local Linux run would have caught this
  sooner, but that's a change to how releases are checked, and isn't made here.

## Tested

- **`tests/test_v3_layers.py::test_regions_shade_by_year_with_legend`** passes, including the exact 0, ½ and 1 that
  failed on CI.
- **`scale01` by hand:** float64 values give exactly 0, 0.5 and 1, and float32 values stay float32.
- **The suite:** 198 Python tests (with the browser tests required), 27 node tests and 26 infra tests pass.
