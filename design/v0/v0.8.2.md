# v0.8.2 — The release log masks the AWS account ID

v0.8.1 made the deploy role a secret, so its ARN no longer shows in the release log. Its log still held the account ID
once: CDK prints the stack's ARN when it deploys, and that ARN names the account. The ID is on sos-forge's private
list, and no tracked file names it.

## What it decides

**The AWS sign-in step asks GitHub to mask the account ID.** `aws-actions/configure-aws-credentials` takes
`mask-aws-account-id: true` and registers the ID with GitHub, which hides it everywhere it appears later in the job's
log, CDK's output included.

**A test keeps it on.** `tests/test_workflows.py::test_aws_account_id_is_masked` requires the setting on every step
that signs in to AWS, and fails naming the workflow without it.

## What it does not decide

- **Earlier logs.** Every release log through v0.8.1 shows the ID in the stack's ARN. AWS doesn't treat an account ID
  as secret, and Steve chose to keep those logs.
- **The 360 video recipe.** v0.8.1's record moved it to v0.8.2; it moves to v0.8.3.

## Tested

- **`tests/test_workflows.py::test_aws_account_id_is_masked`:** passes on this `release.yml`, and fails on v0.8.1's,
  naming it.
- **After release, by hand:** the release log is searched for the account ID.
- **The suite:** 186 Python tests (with the browser tests required), 27 node tests and 23 infra tests pass.
