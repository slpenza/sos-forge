# v0.7.1 — sos-forge's own checks don't count as visitors

v0.7.0's counts went live at 22:26 UTC on 24 Nov 2026. By 22:29 the counts table held 4 visits and 4 views, one for
each of home, the simulator, What's new and Suggest: the release's post-deploy smoke check, which loads each page in
headless Chrome. With counting on, those pages send their views like any visitor's. Every release would have added
four visits that no one made.

## What it decides

**The smoke check answers the pages' counts itself.**
- **How:** `tools/smoke.py`'s `uncounted(page)` routes `POST /api/hit` to an answer in the browser before each page
  loads. The page still sends its view, and the check still sees it answered, but nothing reaches the counter.
- **Why not turn counting off:** the check runs against the live site, whose `config.json` turns counting on.
  Answering in the browser checks the real page, and keeps the live counts to people.
- **The same for checks run by hand:** any audit script run against the live site must answer `/api/hit` the same
  way. The test suite's pages never count: the fixture site leaves counting off, and the one test that turns it on
  answers the hits itself.

## What it does not decide

- **Today's 4 visits and 4 views.** They came from v0.7.0's own check. Removing those rows from the counts table is a
  deletion in production data, and Steve's to decide.

## Tested

- **`test_browser.py::test_checks_are_not_counted`:** a page with counting on, opened as the smoke check opens it,
  sends its view, and the view is answered 204 in the browser, with no problems recorded.
- **`test_counts_views_and_downloads` still passes.** The test's own handler takes precedence over the watcher's.
- **The suite:** 172 Python tests (with the browser tests required), 23 node tests and 21 infra tests pass.
